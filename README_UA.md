# InfoBot — інформаційний каталог 0.1 і підтримка

> Для поточної робочої версії див. [ручну перевірку та запуск на Linux](MANUAL_CHECK.md).
> Вікно спрощено до вкладок «Запуск», «Електронна пошта» та «Підключення».
> Опис демо, локального редактора FAQ, перегляду листа й кнопки резервної копії нижче належить попередньому інтерфейсу; цих елементів у поточному вікні немає. FAQ редагується через Telegram.


Версія від 7 листопада 2026 року. Програма працює на вашому комп’ютері та використовує стандартні модулі Python, зокрема Tkinter, SQLite, HTTPS, smtplib та email. Установлення сторонніх Python-бібліотек не потрібне.

Меню, типові відповіді, повідомлення клієнта й спеціаліста, вікно налаштувань, власні повідомлення про помилки та ця інструкція — українською. Технічні ключі JSON збережені; команди підтримки описані нижче.

## Поточна клієнтська навігація

Джерело реалізації — [технічний документ 0.1](docs/InfoBot_Content_Technical_v0_1.docx).
Початковий екран: «Створення виробництва», «Розвиток виробництва»,
«Відновлення виробництва», «Допомогти з вибором», «Звернутися до підтримки».
Після пояснення напряму оберіть 50/50, 70/30 або 80/20 (грант / власний внесок),
прочитайте умови й підтвердьте інформаційний вибір. Це співфінансування,
а не три окремі програми; застосовність усіх поєднань не гарантується.

Помічник збирає місце реалізації, опис діяльності та походження обладнання.
Він зберігає опис і дає підказки без автоматичного висновку про право на грант.
Після підтвердження доступні «Умови та фінансування», «Подання та розгляд заяви»,
«Після схвалення гранту», FAQ, підтримка та зміна вибору. Додано документи
про пошкодження з поверненням до фактичного попереднього екрана.

Каталог містить 52 екрани. Нові вісім FAQ показуються по чотири на сторінку;
21 попереднє запитання збережено в окремому списку. Обидва списки використовують
один редагований FAQ-каталог. Права спеціаліста перевіряються для кожної дії.
Нові правові FAQ після редагування зберігаються як чернетки; їхній попередній
перегляд та кнопка окремого затвердження доступні в панелі спеціаліста.
Редактор дозволяє змінювати текст, джерело та прив’язки до напряму/співфінансування.

Напрям, співфінансування, історія, опис проєкту й чернетка зберігаються в SQLite
окремо для кожного користувача. Зміна напряму очищає співфінансування й підбір;
зміна співфінансування зберігає напрям. Команди `/start` та `/menu` показують нове
початкове меню внизу чату, зберігаючи чернетку. Наступні переходи редагують це
повідомлення. При відмові редагування новий ID записується лише після успішної
доставки; невдала очистка старих кнопок не повторює надсилання меню.

Підтримка: запитання → ПІБ → компанія/ФОП або «Бізнес ще не зареєстровано» →
телефон → email → перевірка → явне надсилання. Кожне поле можна змінити окремо
з поверненням до перевірки. «Назад» зберігає значення; скасування видаляє чернетку
без створення звернення. Контекст фіксується при відкритті форми, згідно з моделлю
документа; наступна зміна вибору не переписує цей знімок.

Повторна відправка не створює другу заявку. Спеціаліст може прийняти звернення;
клієнт отримує повідомлення в чаті. Вільний текст у відкритому діалозі додається
до звернення, навігаційні натискання — ні. Закриття персоналізоване, з робочими
кнопками повернення та нового запитання. `/continue` продовжує чернетку;
`/ask`, `/support`, `/help` відкривають єдину підтримку.

## Запуск і перевірка

Linux із графічною сесією й Tkinter:

```bash
cd /home/agent/projects/infobot/InfoBot
./START_LINUX.sh
```

Альтернатива — `python3 main.py`. Щоб підхопити оновлення вже запущеного бота,
зупиніть його й запустіть знову через інтерфейс. Автономна перевірка:

```bash
python3 -m unittest discover -s tests
```

Результат поточної реалізації: **207 тестів — OK**; Telegram і SMTP підроблені,
SQLite тимчасова. Реального бота під час розробки не запускали. Для окремого
ручного тесту та копії програми див. [MANUAL_CHECK.md](MANUAL_CHECK.md).

## Міграції та оновлення контенту

Міграції SQLite додають поля редагування, відправки й прийняття спеціалістом
і реєстр старих меню; контакти, відкриті звернення, чернетки та чинні ID меню
зберігаються. Перед оновленням зупиніть програму й зробіть власну резервну копію.
Вісім нових FAQ додаються одноразово до чинного `data/faq_catalog.json`;
перезапуск не повертає видалені FAQ й не скидає внесені редактором зміни.

`content/screens.json` містить тексти екранів, переходи й метадані джерел;
`content/faq_v01.json` — лише початкові тексти нових FAQ. Після імпорту FAQ
оновлюються через адміністративний редактор. Зміна файлу початкових FAQ
не перезаписує чинний каталог. Датований Q01 редагується незалежно від інших
відповідей; зміна тексту прибирає попередню дату й джерела до їх повторної перевірки.
Порядок редагування й погодження — [content/README_UA.md](content/README_UA.md).

## Перед публікацією

Надайте справжній URL політики обробки даних: параметр `privacy_policy_url`
у конфігурації (приклад — `config.example.json`). За відсутності URL бот прямо
повідомляє про це; посилання не вигадується. Значення має бути HTTPS-адресою.

Звірте редакцію Порядку, дату чинності, територіальну матрицю, спеціальні витрати,
персонал, завершення та поточний графік приймання. Ці питання не зняті погодженням
текстів як основи реалізації. Технічні ID, позначення джерел і статуси редакції
не показуються клієнту. Повний перелік — [content/APPROVAL_UA.md](content/APPROVAL_UA.md),
результат реалізації — [docs/IMPLEMENTATION_V01_UA.md](docs/IMPLEMENTATION_V01_UA.md).

Нижче збережено опис попередньої версії 0.4.3 для довідки про її механізми.
Опис старих трьох кнопок, порядку контактів та автоматичного надсилання
після компанії не застосовується до поточної навігації.

## Що змінилося

- У кожному чаті FAQ, підтримка, анкета й панель спеціаліста оновлюють текст і кнопки одного повідомлення меню. Якщо це повідомлення видалено, наступна дія створює його знову.
- У приватному чаті бот після обробки пробує видалити введені команди, зокрема `/start` і `/claim`. Нові звернення, відповіді спеціаліста та закриття надходять окремими сповіщеннями.
- 21 типове запитання про гранти на обладнання з простими відповідями, датою перевірки й посиланням на джерело. Повний список — у **FAQ_UA.md**, примітки щодо оновлень умов — у **RESEARCH_NOTES_UA.md**.
- Після короткого привітання клієнт бачить рівно три кнопки: **«Поширені запитання»**, **«Підтримка»**, **«Запитання спеціалісту»**.
- У **«Підтримці»** є кнопки для свого звернення, анкети, відомостей про дані й Telegram ID.
- `/commands` доступна лише спеціалісту. Під час запуску InfoBot оновлює вбудоване меню Telegram зі списком клієнтських дій.
- Спеціаліст додає, змінює й видаляє FAQ у Telegram або на вкладці **«Запитання та відповіді»**. Зміни доступні одразу, перезапуск не потрібний.
- Після запитання клієнт обов’язково вводить email, телефон, ПІБ і компанію. До завершення всіх полів зберігається чернетка; підтримка її не отримує.
- Після завершення анкети бот реєструє звернення з номером. При закритті звертається до клієнта за ім’ям із ПІБ, наприклад «Олено, дякуємо за звернення!».
- Якщо поштову пересилку ввімкнено, після завершення анкети запитання та всі контакти автоматично додаються до черги листів службі підтримки.
- Наступні повідомлення клієнта надсилаються як доповнення з тією самою темою та номером звернення. Для пов’язування листів використовуються поштові заголовки відповіді; відображення розмови залежить від поштового клієнта.
- Окрема вкладка **«Електронна пошта»** містить параметри SMTP, адреси, захищене поле пароля та попередній перегляд шаблону.
- Демо показує сформований лист без справжнього надсилання.
- Збережені функції спеціаліста, закриття, видалення локального листування, обмеження за Telegram ID та резервного копіювання.

## Що бачить клієнт

Привітання:

> Вітаємо! Я — інформаційний бот про гранти на обладнання для переробних підприємств у межах програми «Зроблено в Україні». Допоможу дізнатися про умови участі, фінансування, подання заявки та використання коштів.
>
> Оберіть розділ:

| Кнопка | Результат |
| --- | --- |
| Поширені запитання | Список запитань сторінками по 6; коротка відповідь і джерело |
| Підтримка | Своє звернення, дії з чернеткою, інформація про дані та Telegram ID |
| Запитання спеціалісту | Запитання → email → телефон → ПІБ → компанія → реєстрація звернення |

Додаткові кнопки керування бачить лише підключений спеціаліст. Перегляд FAQ не потребує заповнення контактів і не створює звернення.

Станом на 06.11.2026 сторінка послуги Дії повідомляє про призупинення приймання заяв. Це відображено в окремій відповіді FAQ. Статус не перевіряється автоматично: перед новою хвилею подання спеціаліст має оновити відповідь. Бот надає довідку та приймає звернення до вашої компанії; державна заявка подається через Дію.

## Швидкий запуск у Windows

1. Повністю розпакуйте архів у папку з правом запису, наприклад `C:\InfoBot`. Запускайте файли з розпакованої папки.
2. Потрібен звичайний Python **3.10 або новіший**, із компонентом Tcl/Tk. Перевірка в командному рядку: `py -3 --version`. Якщо команди немає, спробуйте `python --version`. [Офіційне завантаження Python](https://www.python.org/downloads/windows/).
3. Відкрийте **DEMO_WINDOWS.cmd**. У лівій панелі натисніть «Запитання спеціалісту», напишіть тестове питання. Послідовно введіть email, телефон, ПІБ «Шевченко Олена Іванівна» та компанію ТОВ "Укрхелп". Лише тоді звернення з’явиться у правій панелі спеціаліста. Кнопка **«Переглянути лист»** показує останній сформований лист. У демо інтернет, токен і поштовий пароль не потрібні; справжні листи не надсилаються.
4. Для реального бота запустіть **START_WINDOWS.cmd**. Після налаштування асоціації файлів Python також можна відкривати **START_WINDOW.pyw** без консолі.

VS Code та його розширення Python для запуску цих файлів не потрібні. Вхідний файл програми — `main.py`; файли `__init__.py` окремо не запускаються.

## Оновлення з попередньої версії

1. Зупиніть старого бота й дочекайтеся завершення роботи. Зробіть копію його папки `data`.
2. Розпакуйте новий архів в окрему папку.
3. Якщо налаштування та звернення вже існують, скопіюйте стару папку `data` до нової папки `InfoBot`.
4. Запустіть нову програму. Існуюча база та черга Telegram оновляться автоматично зі збереженням звернень. Якщо використовується той самий Windows-користувач на тому самому ПК, збережений токен можна прочитати й після перенесення папки.
5. Після підключення бота надішліть йому `/start` у Telegram, щоб відкрити статичне меню.

Якщо ви змінювали шаблон листа, перенесіть свій `mail_template.json` окремо. Новий `faq.json` містить добірку про гранти. Редагування з версії 0.4 зберігаються в `data/faq_catalog.json`; під час наступних оновлень переносіть цей файл разом із `data`.

У версії 0.4 команда `/support` відкриває розділ «Підтримка». Для нового запитання використовуйте `/ask` або кнопку «Запитання спеціалісту». `/start` завжди показує привітання й меню, зберігаючи наявну чернетку; продовження анкети — через `/continue` або «Підтримка».

Якщо у вихідній версії ще немає налаштувань пошти, налаштуйте пересилання після оновлення. Листи формуються для **нових прийнятих повідомлень клієнта**, зокрема доповнень до вже відкритих звернень. Якщо в старому зверненні немає обов’язкових контактів, бот запитає їх перед передаванням наступного уточнення. Старий номер і попередня історія зберігаються.

## Налаштування Telegram

1. В офіційному [@BotFather](https://t.me/BotFather) створіть окремого тестового бота командою `/newbot`.
2. Увімкніть двоетапну перевірку Telegram-акаунта власника. Вона захищає акаунт; програма працює через токен Bot API та не перевіряє облачний пароль Telegram.
3. Вставте токен у поле на вкладці **«Запуск»**, натисніть **«Зберегти й запустити»**. Токен вводьте лише на власному ПК.
4. Натисніть **«Відкрити бота»**, потім «Запустити» у Telegram.
5. Для ролі спеціаліста скопіюйте команду `/claim ...` із локального вікна та надішліть її своєму боту. Код одноразовий і діє 10 хвилин. Новий успішно використаний код змінює спеціаліста.

Один акаунт є спеціалістом. Для окремої ролі клієнта використайте другий акаунт або демо. Якщо пошту вже налаштовано й увімкнено, бот може приймати звернення без підключеного Telegram-спеціаліста. Для відповіді через бота підключіть спеціаліста.

У полі учасників тесту можна вказати дозволені Telegram ID через кому. Порожній список означає доступ будь-кому, хто знайде бота. Для отримання власного ID є команда `/id`, поки доступ не обмежений.

## Обов’язкова анкета після запитання

Після тексту запитання бот послідовно просить чотири поля:

| Крок | Обов’язкові дані | Приклад |
| --- | --- | --- |
| 1 | Одна електронна адреса | `olena@example.test` |
| 2 | Номер телефону з кодом країни або звичайний український мобільний номер | `+380671234567` або `0671234567` |
| 3 | ПІБ у порядку **Прізвище Ім’я По батькові** | `Шевченко Олена Іванівна` |
| 4 | Компанія з префіксом ТОВ та назвою в лапках | `ТОВ "Укрхелп"` |

Формат перевіряється на кожному кроці. Неправильне значення не переводить анкету далі. Телефон нормалізується до міжнародного запису; український номер 0671234567 зберігається як +380671234567. ПІБ вводяться повністю, без ініціалів. Складові імені чи прізвища через дефіс і апостроф підтримуються. Якщо по батькові немає, замість нього вкажіть `—`. Для компанії також приймаються парні лапки «» та “”; результат зберігається як ТОВ "Назва".

До завершення всіх полів немає зареєстрованої нової заявки, листа підтримці чи повідомлення спеціалісту. Чернетка зберігається в SQLite і відновлюється після перезапуску. `/continue` або кнопка **«Продовжити анкету»** в розділі «Підтримка» повертає до поточного кроку. `/back` / **«Назад»** дозволяє виправити попереднє поле. `/cancel` видаляє чернетку з локальної бази. `/delete_me` видаляє чернетку та закриває наявне звернення клієнта.

Після компанії звернення автоматично реєструється. Дані потрапляють у лист та картку спеціаліста. Для доповнень до того самого відкритого звернення вже заповнені контакти використовуються повторно. Після закриття нова заявка потребує нової анкети.

Ім’я для особистого звернення береться з другого компонента введених ПІБ, а не з псевдоніма Telegram. Приклад повідомлення при закритті:

> Олено, дякуємо за звернення! Ваше звернення №123 закрите.

Для поширених українських імен використовується клична форма; незнайомі програмі імена зберігаються в записі клієнта. Для старих заявок без нових контактних полів програма за можливості використовує збережене ім’я профілю Telegram; відсутнє ім’я не вигадується.

## Пошта: зараз можна залишити вимкненою

Поштову скриньку ви створюєте самостійно пізніше. До цього залиште прапорець пересилання вимкненим. Бот працюватиме з Telegram-спеціалістом; у демо доступний і поштовий сценарій.

Коли скринька буде готова, відкрийте вкладку **«Електронна пошта»** та заповніть:

| Поле | Що вказати |
| --- | --- |
| SMTP-сервер | Ім’я сервера для надсилання, яке надає ваш поштовий сервіс |
| SMTP-порт | Порт із налаштувань сервісу |
| Захист з’єднання | `ssl` для TLS від початку з’єднання або `starttls` для обов’язкового переходу на TLS |
| Логін поштової скриньки | Логін, наданий сервісом; часто це повна адреса скриньки |
| Адреса відправника | Адреса створеної вами скриньки бота, дозволена сервісом для цього логіна |
| Адреса отримувача | Одна скринька підтримки, куди мають надходити питання клієнтів |
| Пароль застосунку для SMTP | Облікові дані SMTP, дозволені сервісом; за потреби окремий пароль застосунку |

Типові порти — 465 для `ssl` і 587 для `starttls`, але використовуйте конкретні параметри свого сервісу. Програма перевіряє TLS-сертифікат; передавання пароля незахищеним SMTP не підтримується.

Відправник і отримувач можуть бути тією самою скринькою, якщо це дозволено вашим поштовим сервісом. Для окремого отримувача використайте адресу працівника або служби, яка обробляє звернення. Клієнт не може змінити адресата листа через текст свого питання.

Після заповнення ввімкніть прапорець **«Автоматично надсилати прийняті запитання та доповнення на пошту»**, збережіть налаштування та запустіть бота. Натискання «Зберегти налаштування» саме по собі не надсилає листа.

Підтримується вхід SMTP за логіном і паролем/паролем застосунку. Якщо ваш сервіс або політика організації дозволяє лише OAuth2, для нього потрібна окреме доопрацювання авторизації. Вартість і ліміти пошти залежать від обраного сервісу; у коді немає залежності від платного API розсилок.

## Який лист отримує підтримка

Тема за замовчуванням: **`[InfoBot] Звернення №123`**.

У тексті будуть номер звернення, тип події, час прийняття ботом у UTC, обов’язкові ПІБ, компанія, email і телефон, дані профілю Telegram та текст питання. Заголовок Reply-To містить перевірену за форматом контактну адресу клієнта: підтримка може відповісти на неї звичайним електронним листом. Адреса отримувача звернень залишається заданою власником у налаштуваннях.

Повний редагований шаблон знаходиться у **mail_template.json**. Приклад готового листа — **MAIL_EXAMPLE.txt**. Змінивши шаблон, перезапустіть програму. Вікно **«Переглянути шаблон листа»** використовує вигадані тестові дані.

Поля тексту шаблону:

| Поле | Значення |
| --- | --- |
| `{ticket_id}` | Номер звернення |
| `{message_number}` | Порядковий номер повідомлення клієнта в цьому зверненні |
| `{event_label}` | Нове звернення або доповнення |
| `{accepted_at}` | Час прийняття ботом, UTC |
| `{client_name}` | Ім’я профілю Telegram |
| `{client_full_name}` | ПІБ, уведені клієнтом |
| `{client_first_name}` | Ім’я з другого компонента ПІБ |
| `{client_company}` | Компанія у форматі ТОВ "Назва" |
| `{client_email}` | Контактний email клієнта |
| `{client_phone}` | Нормалізований номер телефону |
| `{client_username}` | Ім’я користувача Telegram або позначка про його відсутність |
| `{client_id}` | Telegram ID клієнта |
| `{client_link}` | Посилання на Telegram-профіль |
| `{question}` | Текст прийнятого повідомлення |
| `{bot_username}` | Ім’я користувача бота |

Тіло обов’язково має містити `{ticket_id}` і `{question}`. У старому власному шаблоні без усіх нових полів бот автоматично додає блок контактів, щоб email, телефон, ПІБ та компанія потрапили в лист. У темі дозволені лише `{ticket_id}` і `{message_number}`. Не використовуйте вирази Python або доступ через крапку в полях. Для буквальних фігурних дужок у шаблоні пишіть `{{` і `}}`.

Автоматичне читання вхідної скриньки та пересилання відповіді з пошти у Telegram не реалізовані. Підключений спеціаліст відповідає через бота кнопкою **«Відповісти»** або командою `/reply НОМЕР текст`.

## Черга, статуси та повтори

Для нового звернення постановка листа в чергу відбувається лише після заповнення всіх обов’язкових контактів. До цього бот підтверджує збереження локальної чернетки та пропонує наступний крок. Статус **«передано SMTP»** з’являється після того, як поштовий сервер прийняв лист. Це не підтвердження прочитання або потрапляння саме до папки «Вхідні»; перевірте також спам і правила своєї скриньки.

За тимчасового збою мережі чи відповіді SMTP 4xx лист залишається у SQLite та повторюється зі зростанням інтервалу, до 5 хвилин. Помилка пароля, адреси, TLS або остаточна відмова SMTP зупиняє поштове надсилання, зберігаючи звернення та лист. Перевірте параметри, за потреби перезапустіть програму; після виправлення можна натиснути **«Повторити листи з черги»**.

Після перезапуску черга зберігається, а невдалі листи пробуються знову. Якщо ви зміните адресу отримувача, ще не надіслані листи підуть на адресу з чинних налаштувань. Уже передані серверу листи повторно за звичайного запуску не надсилаються.

Поштовий потік працює окремо від Telegram та графічного вікна. На час очікування SMTP меню й прийняття інших Telegram-повідомлень продовжують працювати. Під час виходу дочекайтеся завершення поточного мережевого запиту.

Якщо з’єднання обірвалося після прийняття листа SMTP-сервером, але до отримання підтвердження програмою, можливий повтор. Сталий Message-ID допомагає поштовому клієнту пов’язати спроби, але гарантії «рівно один раз» немає.

## Звернення та видалення

Одночасно в клієнта одне відкрите звернення. Наступний текст додається до нього; після закриття можна створити нове. Ліміт одного повідомлення — 2000 одиниць UTF-16. Приймаються лише текстові запитання; вкладення та голосові не завантажуються.

Клієнт або спеціаліст може закрити звернення кнопкою з підтвердженням. Команда `/delete_me` є явною вимогою клієнта закрити й видалити своє відкрите звернення.

Після закриття запис, ПІБ, контактні email і телефон, компанія, дані Telegram, локальна історія та ще не розпочаті поштові завдання цього звернення видаляються з робочої бази. Лист, надсилання якого вже розпочалося, може бути прийнятий сервером під час закриття звернення. **Листи, що вже надійшли в поштову скриньку, залишаються там**; строками зберігання керує власник скриньки.

Якщо ввімкнено відповідний прапорець, бот також пробує видалити пов’язані повідомлення Telegram. Діють обмеження Telegram, зокрема строк 48 годин для звичайних повідомлень. Для старішого повідомлення меню, у якому відкрито звернення, бот пробує оновити екран і прибрати дані звернення. Кнопка «Головне меню» у сповіщенні про закриття відкриває меню знову, якщо його видалено.

Клієнтські дії доступні кнопками під повідомленнями. Також підтримуються `/start`, `/menu`, `/faq`, `/support`, `/help`, `/ask`, `/mine`, `/continue`, `/back`, `/cancel`, `/id`, `/privacy` та `/delete_me`. Спеціаліст може надіслати `/commands` або відкрити «Команди спеціаліста» в панелі. Йому також доступні `/admin`, `/tickets` і `/reply`.

## Захист облікових даних

Токен знаходиться у `data/token.secret`, пароль SMTP — у `data/smtp.secret`. У Windows вони захищені DPAPI для поточного користувача Windows. Після перенесення на інший ПК або до іншого Windows-користувача введіть облікові дані заново.

На Linux/macOS секрети зберігаються у файлах із правами `0600` без шифрування. Для консольного запуску підтримуються змінні середовища `INFOBOT_TOKEN` та `INFOBOT_SMTP_PASSWORD`; вони мають пріоритет перед відповідними файлами. Не передавайте секрети параметрами командного рядка.

У `data/config.json` і `config.example.json` пароля та токена немає. Журнал програми не записує тексти запитань, поштовий пароль, токен або повні серверні відповіді, які можуть містити приватні дані. Копії конфігурації містять поштові адреси та логін; вони є налаштуваннями власника.

## Резервна копія та відновлення

Коли живого бота запущено, кнопка **«Резервна копія»** створює незашифровану узгоджену копію SQLite у `data/backups`. Вона містить відкриті звернення з контактами, незавершені чернетки анкет, чергу Telegram, чергу пошти та службовий номер останнього Telegram-сигналу. Поруч створюється файл `*.faq.json` з актуальним каталогом FAQ. Токен, пароль SMTP та JSON-конфігурація до копій не входять.

Для відновлення зупиніть бота, збережіть окремо поточну базу, скопіюйте вибраний файл копії до `data` та перейменуйте його на `bot_ЧИСЛО.sqlite3`, прибравши дату з імені. Число у назві копії відповідає цьому боту. Налаштування спеціаліста й пошти відновіть зі свого `data/config.json` або через вікно, а секрети за потреби введіть знову.

Для відновлення FAQ скопіюйте відповідний файл `*.faq.json` у `data/faq_catalog.json` при зупиненій програмі. Перед заміною збережіть поточний каталог окремо. База й FAQ копіюються послідовно; це не єдина транзакція для двох файлів.

Стара копія може містити звернення, видалені пізніше. Відновлення старої черги може спричинити повторне надсилання листів чи Telegram-повідомлень. Копіями та строком їх зберігання керує власник.

## Редагування довідки та перевірка

На комп’ютері: вкладка **«Запитання та відповіді»** → виберіть запитання → змініть текст → **«Зберегти»**. Для нового: **«Додати запитання»**, заповніть поля й збережіть. Видалення потребує підтвердження.

У Telegram: **«Панель спеціаліста» → «Редагувати FAQ»**, або **«Поширені запитання» → «Редагувати FAQ»**. Відкрийте потрібний пункт і виберіть, що змінити: запитання, відповідь або джерело. Нове запитання додається в три кроки: заголовок → відповідь → HTTPS-джерело або `—`. `/cancel` чи вихід у меню скасовує незавершене редагування. Час на введення — 30 хвилин. Збережені зміни діють одразу й залишаються після перезапуску.

Редагування доступне лише поточному спеціалісту. Якщо каталог змінено паралельно з іншого вікна або Telegram, старий текст не перезапише новий: оновіть список і повторіть зміну. На комп’ютері перед оновленням скопіюйте незбережений текст із полів.

Початкові 21 відповідь містяться у `faq.json`. Після першого збереження використовується `data/faq_catalog.json`. Не редагуйте ці файли вручну під час роботи. Дозволено 1–60 запитань; останнє видалити не можна. Заголовок — один рядок до 60 одиниць UTF-16, відповідь — до 3000, джерело — HTTPS-посилання або порожнє поле. Після ручної зміни відповіді або джерела попередня позначка перевірки прибирається. У Telegram зміна відповіді також прибирає попереднє джерело; його можна додати окремою дією.

Редагування FAQ у вкладці демо ізольоване: воно не змінює справжній каталог. Кнопка **«Почати знову»** завантажує актуальні відповіді з основного каталогу.

Автономні тести без справжнього Telegram та SMTP:

```text
py -3 main.py --self-test
```

Або **TEST_WINDOWS.cmd**. Консольний режим після налаштування: `py -3 main.py --console`. Зупинка — Ctrl+C.

На Linux/macOS використовуйте `python3`; для графічного вікна потрібні Tkinter та графічна сесія. Публічний IP і вхідні порти для бота не потрібні. Одночасно запускайте один екземпляр на один токен. Поки ПК вимкнений, програма закрита або немає інтернету, нові звернення не обробляються.

## Якщо виникла помилка

| Ситуація | Що перевірити |
| --- | --- |
| Python не знайдено | Установіть звичайний Python із Tcl/Tk; перевірте `py -3 --version` |
| Немає tkinter | Додайте Tcl/Tk в установці Python; перевірка: `py -3 -m tkinter` |
| Telegram 401 | Повний токен, його актуальність у BotFather |
| Telegram 409 | Інші запущені копії, webhook; для тесту використайте окремого бота |
| Звернення не приймаються | Підключіть спеціаліста або налаштуйте й увімкніть пошту |
| Листи у статусі перевірки | SMTP-логін, пароль застосунку, адреси, порт і спосіб TLS |
| Листи у черзі | Інтернет, доступ до SMTP, ліміти сервісу; дочекайтеся повтору |
| SMTP прийняв лист, але його немає у вхідних | Спам, правила скриньки, правильність адреси, журнали поштового сервісу |
| Помилка шаблону | Дужки, допустимі поля, наявність question і ticket_id у тілі |
| Немає запису в папку | Розпакуйте в папку свого користувача з правом запису |

Документація: [Telegram Bot API](https://core.telegram.org/bots/api), [SMTP у Python](https://docs.python.org/3/library/smtplib.html), [формування листів у Python](https://docs.python.org/3/library/email.message.html).
