# Каталог клієнтської навігації

`navigation.json` містить українські тексти, підписи, стабільні ідентифікатори,
зв’язки розділів, матрицю співфінансування, прив’язки FAQ та анкету підтримки.
Редагуйте при зупиненій програмі; зміни набувають чинності після перезапуску.
Перевірка: `python3 -m unittest discover -s tests` із кореня репозиторію.

- `directions`: `create`, `develop`, `restore`; `ratios`: `50_50`, `70_30`, `80_20`.
  Ідентифікатори не залежать від підписів: не перейменовуйте їх при зміні текстів.
- `sections.*.children` визначає порядок підрозділів з `answers`.
  Кожен підрозділ належить рівно одному розділу.
- `answers.*.common` — спільний запис; `overrides.create` — для напряму;
  `overrides["develop:70_30"]` — для поєднання, з найвищим пріоритетом.
- `combinations.<direction>.<ratio>` — запис умов і `availability`:
  `unconfirmed`, `available`, `unavailable`. Лише затверджений запис з
  `unavailable` блокує підтвердження. Відсутній запис не означає відмову.
- Запис відповіді: `summary`, `conditions`, `next_step`, `source_url`,
  `source_point`, `status`. Статуси: `pending`, `draft`, `approved`.
  Лише `approved` показує нормативний текст; інші показують повідомлення
  «Умови уточнюються». Для затвердження обов’язкові всі поля, HTTPS-джерело
  та пункт. Кожне поле обмежене 700 символами.
- `selection_questions`: до восьми записів `{id, status, text}`;
  лише затверджені запитання показуються в допомозі. Відповіді не обчислюють
  право на фінансування. Поки що список порожній.
- `faq_bindings.common`, `.directions`, `.combinations` — списки ID FAQ;
  `*` включає всі поточні FAQ. Наразі всі старі FAQ залишені загальною довідкою
  з попередженням про необхідність перевірити відповідність сценарію.

FAQ залишається редагованим у панелі спеціаліста Telegram: початковий файл
`faq.json`, зміни — `data/faq_catalog.json`. Новий каталог задає лише прив’язки,
тому редагування й видалення FAQ відразу враховуються без копіювання відповідей.
Нормативний каталог через редактор FAQ не редагується.

SQLite автоматично додає таблицю `client_navigation` та поля `grant_context`
і `form_version`; старе поле організації `client_company` збережене.
Контекст звернення фіксується при надсиланні: поточний вибір і початкове місце
відкриття підтримки. Контакти та чернетки не містяться в каталозі контенту.
