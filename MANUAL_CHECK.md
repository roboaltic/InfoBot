# Ручна перевірка поточної версії

## Підготовка на Linux

Потрібні Python 3.10+, стандартні модулі Python та вихідний доступ до Telegram HTTPS.
Для вікна потрібні Tkinter і графічна сесія. Сторонні Python-пакети не потрібні.
Команди нижче наведені для виконання вручну; під час підготовки бот не запускався.

Із каталогу проєкту:

```bash
python3 -m unittest discover -s tests
python3 main.py
```

Перша команда запускає автономні тести, друга відкриває вікно. Бот починає роботу після
«Зберегти й запустити». Після налаштування серверний режим без вікна:

```bash
python3 main.py --console
```

Зупинка консолі — Ctrl+C. ПК має залишатися увімкненим і підключеним до інтернету.

## Окрема тестова база

Параметра `--db` або змінної оточення для шляху БД немає. Код обирає
`data/bot_<ID бота>.sqlite3` відносно каталогу вихідного коду, а не поточного каталогу shell.
Зміна робочого каталогу не ізолює дані. Для ручної перевірки використайте окрему
копію програми та окремого тестового бота:

```bash
check_root=$(mktemp -d /tmp/infobot-check.XXXXXX)
cp -R main.py infobot faq.json mail_template.json config.example.json "$check_root/"
mkdir "$check_root/data"
cp "$check_root/config.example.json" "$check_root/data/config.json"
python3 "$check_root/main.py"
```

Тестова БД з'явиться у `$check_root/data/bot_<ID тестового бота>.sqlite3`.
Не копіюйте робочу папку `data`. Використовуйте токен тестового бота і переконайтеся,
що `INFOBOT_TOKEN` та `INFOBOT_SMTP_PASSWORD`, якщо задані, належать тестовому середовищу:
вони мають пріоритет над файлами секретів. Тестовий каталог зберігається до ручного видалення.
Автоматичні тести самі використовують тимчасові БД або SQLite `:memory:` і піддельні клієнти.

## Конфігурація без секретів

Шаблон — `config.example.json`, робочий файл — `data/config.json`.

- `operator_id`: ID диспетчера; початково 0, підключення через одноразову `/claim`.
- `allowed_user_ids`: список дозволених ID; порожній список дозволяє всіх. Для перевірки вкажіть тестові акаунти.
- `delete_telegram_on_close`: чи пробувати видаляти листування з Telegram при закритті.
- `mail.enabled`: для перевірки лише Telegram залиште `false`.
- При ввімкненій пошті: `mail.host`, `mail.port`, `mail.security` (`ssl` або `starttls`),
  `mail.username`, `mail.sender`, `mail.recipient`; використовуйте тестову скриньку.
- Токен: поле у вікні → `data/token.secret`, або `INFOBOT_TOKEN`.
- Пароль SMTP: поле у вікні → `data/smtp.secret`, або `INFOBOT_SMTP_PASSWORD`.

Секрети не додавайте до JSON чи Git. На Linux файли секретів мають права 0600;
формат зберігання не шифрує їх. `faq.json` та `mail_template.json` потрібні для запуску;
локальні зміни FAQ зберігаються у `data/faq_catalog.json`.

## Короткий сценарій

1. Відкрийте вікно: є «Запуск», «Електронна пошта», «Підключення», немає демо.
   Запустіть тестового бота. Підключіть диспетчера командою `/claim` із вікна.
   Для клієнта використайте інший Telegram-акаунт.
2. Клієнт: `/start` → три основні кнопки. Перейдіть у «Підтримка» та назад.
   Перевірте, що навігація змінює одне повідомлення меню. У «Підключення» є ID,
   ім'я / @username і місцевий час першого звернення.
3. FAQ: список, сторінки, відповідь, джерело, повернення в меню. Заявка не створюється.
   Диспетчер: відкрийте панель і редагування FAQ; скасуйте введення без збереження.
4. Клієнт: «Запитання диспетчеру» → текст → email → телефон → ПІБ → компанія.
   Перевірте відхилення помилкового email, «Назад» і продовження чернетки.
   Заявка та сповіщення диспетчеру з'являються лише після завершення анкети.
5. Диспетчер: відкрийте картку, дайте відповідь. Клієнт отримує окреме сповіщення.
   Закрийте заявку з підтвердженням. Натисніть «Головне меню» в окремих сповіщеннях
   про закриття в обох чатах: меню має відкритися, кнопки мають працювати.
   Якщо є сповіщення попередньої версії, перевірте його кнопку також.
6. Якщо збереглося старе повідомлення статичного меню після заміни, його кнопки
   мають ігноруватися, включно з адміністративними, без скасування поточного введення.
   Без збереженого ID меню відкрийте заново через `/start`.
7. Зупиніть і знову запустіть програму. Список підключень зберігається без дублікатів,
   повторне звернення не змінює час першого підключення.

Відмову надсилання заміни, повторну спробу та спробу зняти старі кнопки перевіряють
автономні регресійні тести; для цього не потрібно імітувати збій реального Telegram.
