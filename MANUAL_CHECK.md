# Ручна перевірка поточної версії

## Графічний запуск Linux

Виконайте `./START_LINUX.sh` із каталогу проєкту. Потрібні графічна сесія та Tkinter;
для Ubuntu/Debian пакет встановлюється командою `sudo apt-get install python3-tk`.
На вкладці «Запуск» вставте токен BotFather: текст ключа відображається без маскування.
Натисніть «Зберегти й запустити». Підключення спеціаліста — командою `/claim` із форми.
Кнопка «Зупинити» зупиняє бота; «Відкрити бота» відкриває його в Telegram.

## Форма запуску без Tkinter

Із каталогу проєкту виконайте `python3 main.py --setup`.
Форма в терміналі приховано запитає токен BotFather, ID спеціаліста та дозволених
користувачів. Enter зберігає поточні значення; для списку користувачів `*` дозволяє всіх.
ID спеціаліста 0 означає підключення через команду `/claim`, яку буде показано після запуску.
Після підтвердження `y` налаштування зберігаються в `data`, і бот працює до Ctrl+C.
За замовчуванням пошта вимкнена; раніше збережені параметри пошти залишаються чинними.
Токен не потрапляє до JSON або Git. На Linux файл `data/token.secret` має права 0600.
Для окремої тестової бази запускайте форму з окремої копії програми, як описано нижче.

## Підготовка на Linux

Потрібні Python 3.10+, стандартні модулі Python та вихідний доступ до Telegram HTTPS.
Для вікна потрібні Tkinter і графічна сесія. Сторонні Python-пакети не потрібні.
Команди нижче наведені для виконання вручну; під час підготовки бот не запускався.

Із каталогу проєкту:

```bash
python3 -m unittest discover -s tests
python3 main.py
```

Перша команда запускає автономні тести, друга відкриває вікно. Бот починає роботу після
«Зберегти й запустити». Після налаштування серверний режим без вікна:

```bash
python3 main.py --console
```

Зупинка консолі — Ctrl+C. ПК має залишатися увімкненим і підключеним до інтернету.

## Окрема тестова база

Параметра `--db` або змінної оточення для шляху БД немає. Код обирає
`data/bot_<ID бота>.sqlite3` відносно каталогу вихідного коду, а не поточного каталогу shell.
Зміна робочого каталогу не ізолює дані. Для ручної перевірки використайте окрему
копію програми та окремого тестового бота:

```bash
check_root=$(mktemp -d /tmp/infobot-check.XXXXXX)
cp -R main.py infobot content faq.json mail_template.json config.example.json "$check_root/"
mkdir "$check_root/data"
cp "$check_root/config.example.json" "$check_root/data/config.json"
python3 "$check_root/main.py"
```

Тестова БД з'явиться у `$check_root/data/bot_<ID тестового бота>.sqlite3`.
Не копіюйте робочу папку `data`. Використовуйте токен тестового бота і переконайтеся,
що `INFOBOT_TOKEN` та `INFOBOT_SMTP_PASSWORD`, якщо задані, належать тестовому середовищу:
вони мають пріоритет над файлами секретів. Тестовий каталог зберігається до ручного видалення.
Автоматичні тести самі використовують тимчасові БД або SQLite `:memory:` і піддельні клієнти.

## Конфігурація без секретів

Шаблон — `config.example.json`, робочий файл — `data/config.json`.

- `operator_id`: ID спеціаліста; початково 0, підключення через одноразову `/claim`.
- `allowed_user_ids`: список дозволених ID; порожній список дозволяє всіх. Для перевірки вкажіть тестові акаунти.
- `delete_telegram_on_close`: чи пробувати видаляти листування з Telegram при закритті.
- `mail.enabled`: для перевірки лише Telegram залиште `false`.
- При ввімкненій пошті: `mail.host`, `mail.port`, `mail.security` (`ssl` або `starttls`),
  `mail.username`, `mail.sender`, `mail.recipient`; використовуйте тестову скриньку.
- Токен: поле у вікні → `data/token.secret`, або `INFOBOT_TOKEN`.
- Пароль SMTP: поле у вікні → `data/smtp.secret`, або `INFOBOT_SMTP_PASSWORD`.

Секрети не додавайте до JSON чи Git. На Linux файли секретів мають права 0600;
формат зберігання не шифрує їх. `content/navigation.json`, `content/screens.json`, `content/faq_v01.json`, `content/faq_v02.json`, `faq.json` та `mail_template.json` потрібні для запуску;
локальні зміни FAQ зберігаються у `data/faq_catalog.json`.

## Короткий сценарій

1. Відкрийте вікно: є «Запуск», «Електронна пошта», «Підключення», немає демо.
   Запустіть тестового бота. Підключіть спеціаліста командою `/claim` із вікна.
   Для клієнта використайте інший Telegram-акаунт.
2. Клієнт: `/start` → три напрями, «Допомогти з вибором», «Звернутися до підтримки».
   Перевірте пояснення напрямів. Після пояснення кожного напряму оберіть 50/50, 70/30 та 80/20.
   На картці показано умови, документ, пункт і опис норми.
   Натисніть «Перейти до меню гранту». Заголовок меню містить напрям і співфінансування.
3. Відкрийте всі три розділи та їхні 11 підрозділів, FAQ і джерело відповіді.
   «Назад» повертає на попередній рівень, «Перейти до меню гранту» — до поточного вибору.
   Зміна співфінансування зберігає напрям; зміна напряму скидає співфінансування.
   Перевірте також документи про пошкодження з пояснення відновлення та з документів.
   Пройдіть помічник: адреса → діяльність → обладнання → підсумок без визначення права.
   Нові FAQ показуються по чотири; перенесені старі відповіді доступні
   спеціалісту та з’являються клієнту лише після погодження щодо редакції 0.2.
   Спеціаліст: змініть новий FAQ, перевірте чернетку, перезапустіть тестову копію,
   затвердьте текст окремою кнопкою та перевірте публікацію. Змініть його прив’язку.
4. Відкрийте підтримку з конкретного підрозділу: запитання → ПІБ → компанія або ФОП
   → телефон → email → перевірка → «Надіслати». Окремо перевірте кнопку
   «Бізнес ще не зареєстровано», неправильний email, повернення зі збереженням значень,
   «Редагувати дані» з вибором кожного поля й поверненням прямо до перевірки та «Скасувати». До надсилання звернення й сповіщення не створюються.
   Повторіть без вибору гранту: відсутні відомості позначено «Не обрано».
5. На перевірці звірте напрям, співфінансування й вихідний підрозділ. Надішліть звернення;
   спеціаліст має побачити знімок із моменту створення звернення в картці та сповіщенні.
   Натисніть «Надіслати» повторно: другого звернення бути не повинно.
   Спеціаліст: прийміть звернення; клієнт отримує окреме повідомлення. Дайте відповідь і закрийте
   звернення. Клієнт отримує персональне повідомлення; кнопка в ньому повертає до меню
   гранту або вибору напряму. Перевірте також кнопку старого повідомлення про закриття.
6. Збережіть чернетку, виконайте `/start`: нове початкове меню з’являється внизу
   чату, старі кнопки прибираються, чернетка залишається. Переходи кнопками
   редагують нове повідомлення. `/continue` продовжує анкету.
   Перезапуск зберігає вибір і чернетку.
   Другий клієнт не бачить даних першого; сторонній клієнт не має прав спеціаліста.
7. Натисніть старі кнопки попереднього екрана чи заміненого повідомлення: бот відповідає
   підказкою `/start`, вибір і чернетка не змінюються. Після `/start` нові кнопки працюють.
   Старі організації та контакти читаються без втрати значень; повна стара чернетка
   потребує явного підтвердження перед надсиланням.

Відмову надсилання заміни, повторну спробу та спробу зняти старі кнопки перевіряють
автономні регресійні тести; для цього не потрібно імітувати збій реального Telegram.

## Політика даних і правова перевірка перед запуском

Надайте справжній HTTPS-URL у параметрі `privacy_policy_url` конфігурації
при зупиненій програмі. За відсутності URL перевірка звернення прямо повідомляє,
що політику ще не надано. Для тестової копії використовуйте власну тестову адресу.
Нормативна основа та пріоритетні уточнення — `docs/content_revision_0_2.md`.
Дії перед запуском — `content/APPROVAL_UA.md`. Окремо оновіть датований Q01.
Навігація у відкритому діалозі не повинна створювати доповнень; звичайний текст
додається до звернення. Скасування наразі видаляє чернетку, не створюючи заявки.

## Обов’язкові перевірки редакції 0.2

- B03: зарплатна модель також має щоквартальне документальне підтвердження.
- Q02/Q03: заборона повторного гранту стосується повернення через невиконання
  обов’язкових умов; інші підстави повернення не прирівнюються автоматично.
- B03/B04: пункт 3 постанови №1326 містить точний перелік змін із застосуванням
  з 24.06.2022, а не правило для всіх жовтневих змін.
- A05/Q08: пункт 23 — банк та email/SMS/інші електронні засоби;
  пункт 24 — перенесення за відсутності фінансування; пункт 25 — статус у Дії.
- На джерелах видно документ, пункт та опис; немає службових ID й повторюваних
  загальних застережень редакції 0.1.
- Збережіть чернетку, змініть напрям/частку, поверніться до перевірки та надішліть:
  знімок має відповідати актуальному вибору. Пізніша навігація його не змінює.
- У тестовій копії з FAQ редакції 0.1 перевірте збереження авторських правок,
  видалених записів і чернеток. Відкладене старе меню після перезапуску має
  оновитися до 0.2; звичайні повідомлення діалогу залишаються.
